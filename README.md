### 1. 적금 상품 목록 연동하기

---

서버에서 적금 상품 목록을 불러와서 출력해주세요.

- [x] HTTP client는 "_손쉬운 API 사용을 위해 HTTP client 구현체를 미리 제공하고 있어요. `tosslib` 패키지에서 아래와 같이 import 해서 사용할 수 있어요._"를 참고해주세요.
- [x] 적금 상품 목록 API는 상품 목록 가져오기 (`GET /api/savings-products`) 를 참고해주세요.
- [x] 원단위를 표시할 때 콤마(,) 출력에 유의해주세요.

### 2. 저축 목표 입력 기능 만들기

---

목표 금액, 월 납입액, 저축 기간을 사용자가 입력할 수 있는 기능을 구현해주세요. <br/>
입력한 조건에 맞춰서 하단 적금 상품 목록에 보이는 상품 목록(`ProductList`)을 조건에 맞게 필터링해서 출력해주세요.

**필터링 조건**

- [x] 월 납입액
  - `product.minMonthlyAmount` (최소 월 납입액)보다 크고
  - `product.maxMonthlyAmount` (최대 월 납입액)보다 작아야 함
- [x] 저축 기간
  - `product.availableTerms` (저축 기간)와 동일해야 함

### 3. 적금 상품 목록에서 선택 기능 만들기

---

- [x] 적금 상품 목록에서 적금 상품을 선택하면 오른쪽에 선택 아이콘을 표시해주세요.
- [x] 적금은 하나만 선택할 수 있어요.
- [x] 선택한 적금 상품의 정보는 이후 구현 중 “계산 결과” 탭에서 사용할 예정이에요.

### 4. 계산 결과 탭 만들기

---

"계산 결과" 탭을 클릭하면 `CalculationResult` 컴포넌트가 보이게 `SavingsCalculatorPage` 를 수정해주세요. 그리고 아래 기능들을 구현해주세요.

**계산 결과**

적금 상품 목록에서 사용자가 선택한 적금 상품에 대해 아래 공식에 맞게 금액을 계산해주세요.

- [x] 예상 수익 금액
  - 공식: `최종 금액 = 월 납입액 * 저축 기간 * (1 + 연이자율 * 0.5)`
- [x] 목표 금액과의 차이
  - 공식: `목표 금액과의 차이 = 목표 금액 - 예상 수익 금액`
- [x] 추천 월 납입 금액
  - 공식: `월 납입액 = 목표 금액 ÷ (저축 기간 * (1 + 연이자율 * 0.5))`
  - 1,000원 단위로 반올림
- [x] 만약 사용자가 적금 상품을 선택하지 않았다면 “상품을 선택해주세요”를 출력해주세요.

**추천 상품 목록**

- [x] 사용자가 입력한 조건에 맞는 적금 상품 중 연 이자율이 가장 높은 2개의 상품을 출력해주세요.
- [x] 만약 사용자가 선택한 상품이 있다면 적금 상품 목록과 마찬가지로 선택 아이콘을 표기해주세요.

## 추가 개선 아이디어

**기능**

- [x] [기능] 라우터 ErrorElement 및 에러 바운더리 추가
  - 라우터 ErrorElement와 에러 바운더리를 추가해, 오류 발생 시 UI가 깨지던 문제를 해결하고 안정적인 오류 화면을 표시하도록 개선했습니다.
- [x] [기능]input 입력 디바운싱 적용 (선택)
  - 입력할 때마다 UI가 즉시 계속 바뀌어서 깜빡이는 느낌이 신경 쓰였어요. 그래서 입력이 잠시 멈춘 뒤에만 처리되도록 디바운싱을 적용해, 불필요한 UI 변경을 줄이고 더 안정적인 사용자 경험을 만들었습니다.
- [x] [기능]input 입력값 유효성 검사 + (필요하다면) 간단한 테스트
  - 숫자만 입력되도록 유효성 검사를 추가했고, 금액을 더 쉽게 읽을 수 있도록 자동 콤마 포매팅을 적용했습니다. 이 로직은 직접 입력해보는 것보다 테스트로 확인하는 편이 더 빠르고 확실해서 Vitest로 검증했습니다.
- [x] [기능] 필터링 결과 없을 때 대체 UI 추가
  - 조건에 맞는 저축 상품이 없을 때, 화면이 비어 보이지 않도록 토스 스타일의 담백한 Empty UI를 추가했습니다.
    불필요한 당황 요소를 줄이고, 사용자가 다음 행동을 자연스럽게 이어갈 수 있도록 안내하는 목적입니다.

- 현재 총 상품이 몇개인지 `적금상품(10)` 이렇게 보여줘도 좋을 것 같아요. 추천상품 목록도 마찬가지!

**리팩토링**

- [x] [리팩토링] ContextApi 사용해서 props Drilling 줄이기 - `savingsGoalState`, `savingsProductList`
  - `savingsGoalState`(목표 입력 금액)와 `savingsProductList`(적금 상품 목록)를 전달하기 위해 여러 컴포넌트에서 props를 계속 내려주는 구조가 불편해서, Context API로 묶어 props drilling을 줄였습니다. 필요한 곳에서 바로 상태를 사용할 수 있어 코드 흐름이 더 간단해졌습니다.
- [x] [리팩토링] 상품 목록 컴포넌트 렌더링 최소화
  - 불필요하게 상품 목록 전체가 계속 다시 렌더링되는 문제가 있어서, 상태 변경의 영향을 받지 않는 영역은 분리하고 필요한 부분만 갱신되도록 구조를 조정했습니다. 이를 통해 상품 리스트 렌더링 비용을 줄이고 전체 성능을 조금 더 안정적으로 만들었습니다.

## 고민되는 점

**❓ Context 사용 깊이에 대한 고민**
Context 값을 컴포넌트 트리의 어느 깊이까지 전달해도 괜찮을지 고민됩니다. <br/>
트리가 깊어질수록 다음과 같은 어려움이 생기더라구요

- 어떤 컴포넌트가 어떤 Context 값을 읽는지 추적하기 어려워지고
- 값이 어디서 변경되었는지 디버깅하기가 점점 복잡해짐

<br/>

**❓ Spacing 컴포넌트 활용 방식**
컴포넌트를 리팩토링하다 보니 `<Spacing size={8} />` 같은 간격 전용 컴포넌트가 계속 신경쓰였어요. <br/>

- 저는 `SectionPadding`이라는 컴포넌트를 만들어 간격을 유연하게 조절하도록 구성했는데, 다른 분들은 이런 레이아웃 간격을 어떤 방식으로 관리하시는지 궁금합니다.
- 또는 `Border`를 패딩으로 감싸는 전용 컴포넌트를 만들어 적용하는 방법도 있을 것 같아요

<br/>

**❓ 추천 상품 선택/해제 UX 고민**

추천 상품 목록에서 선택/해제를 허용해야 할지 고민이 됩니다. <br/>
선택을 해제하면 계산 결과가 사라지고 ‘**상품을 선택해주세요**’라는 문구가 뜨는데, 이 과정에서 UI 변화가 다소 급격하게(과하게) 느껴지더라구요 <br/>
생각해본 대안은 다음과 같습니다:

- 계산 결과 영역의 높이를 고정해, 선택 해제 시에도 동일한 공간에서 메시지를 표시하기
- 추천 상품 목록에서는 선택 변경을 허용하지 않도록 제한하기
  이 외에 더 나은 접근 방식이 있을지도 궁금합니다!

<br/>
